Building models

Preparing a model for running

Simile runs a model by executing a program that it has generated behind the scenes.  This program contains all the instructions need to calculate the values of the model variables as they change over time.  Whenever you want to run the model after making any changes to it, you must re-generate this program: this is called “building” the model.   At the same time, the value of all the variables are calculated ready for the start of the simulation.

 

To build the model, select either the “Build in Tcl” or “Build in C++” items in the Model menu.  These generate programs in either of two languages, Tcl or C++, respectively.  Models built in C++ will run many times faster than models built in Tcl, but it is necessary to install an external C++ compiler in order to take advantage of this.  An open source C++ compiler, GNU C, is included in the Simile distribution.  Microsoft Visual C++ is also supported. 

 

The Preferences dialogue window, obtained by selecting the Preferences item in the Edit menu, is used to indicate which C++ compiler, if any, is to be invoked.

 

Installing and using an external C++ compiler is a common source of problems.  If you have difficulty, please check the following points in particular:

 

  1. The directory containing the compiler must be in the search path of the operating system.  To check this, try to execute the compile command, for example, g++, from a command prompt.  If it is not found, you will need to follow the installation instructions for the compiler to set the appropriate environment variables.  A batch file, vcvars32, is included with Microsoft Visual C++ to facilitate this. 
  2. Very old versions of the compilers are not supported.  GNU C 2.95 or more recent is recommended and Microsoft Visual C++ 4.0 or more recent is recommended.  We do not anticipate that future releases of these compilers (released after this version of Simile) will cause any problems, but we cannot be certain of this.

 

Once the model has been built, it can be used again and again, until the model is modified in any way.  Saving the model after building it, results in the build being saved with the model.  This allows users with a C++ compiler to share models requiring faster speeds with those without.  So long as the model is not modified in any way after it is opened, it will be possible to use the “Build in C++” command to recall the previously-generated build.

 

Note the following differences between models built in Tcl and C++

 

  1. Generally it is easier to track down and correct errors in Tcl, an interpreted language, than it is in C++, a compiled language.  The Tcl error messages that result from illegal operations are still rather cryptic, but look for the names of the elements involved, and use these to determine which element caused the problem.  It is not itself named, but it is the one that is influenced by all the named elements.
  2. When asked to perform illegal mathematical operations, such as taking the square root of a negative number, Tcl will raise an error message and halt the simulation, whereas C++ will use an undefined value such as NAN (Not A Number) and continue.  The undefined value will propagate through further calculations.  It is possible to recover from this, unless a state variable (compartment) is affected or a helper is required to use an undefined value.
