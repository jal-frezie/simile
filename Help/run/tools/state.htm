Standard helpers: Save/restore state

The Save/restore state helper enables you to capture the values for all variables in a model at anytime during the course of a simulation and dump them into a file.   This file can be used on a subsequent occasion to assign values to all the variables (including compartments, flows, etc) in the model.   You can thus carry a simulation on from the point where you left off previously: maybe it was taking a long time and you needed to interrupt it to go home; or maybe you want the initial state for a model to be some equilibrium state obtained by running the model until equilibrium is achieved.

 

The generated file is a text file, which simply gives the full path name for all the variables in the model (that is, the variable's label preceded by the names of all the submodels that contain it), followed by the value or values for that variable (plural values if the variable is inside one or more multiple-instance submodels).  

 

You may find it useful to generate this file simply to help in understanding a complex model, since, working alongside the model diagram and equations, it enables you to follow chains of calculations.   So if, for example, one variable has an unexpectedly large value, you can check out all the variables used to calculate it.

 

Since the generated file is a text file, you can also edit it.   This will in fact have no effect for intermediate variables (there values are calculated from their influencing variables), but you might find it a useful way to adjust parameter values or re-set compartment values.

 

Example

This toy model has a fixed-membership submodel with five instances, along with a compartment, flow, parameter and output variable.  

 

 

Saving its state produces a file as follows:

 

/Desktop/flow1=3

/Desktop/comp1=2

/Desktop/var1=1

/Desktop/var2=8

/Desktop/submodel1/var3=1 0.958 2 0.607 3 0.788 4 0.422 5 0.818

 

It's all pretty obvious, except to note that the values for the variable inside the submodel are in pairs: the first value gives the instance number (1, 2, 3...), while the second gives the value for that instance.  (The instance numbers are negative for population submodels.)
