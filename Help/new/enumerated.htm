New enumerated type lists

Enumerated types allow you to refer to a collection of objects by name, rather than by an arbitrary index number. For example, if your model includes a variety of fruit trees, say, oranges, apples, pears and passion fruits, then you may have represented the trees as a multiple instance submodel, with one instance for each type. Model parameters, such as growth rate and productivity, would then have independent values for each species.

 

To make the multiple instances easier to distinguish and more convenient to refer to, enumerated types allow you to name each instance.

 

Enumerated types are defined for a submodel, can be used in that submodel and all contained submodels. The simple approach is to define the enumerated type for the desktop. To do this, double-click in a blank area of the desktop, or select the Properties command from the Model menu.

 

The dialogue box allows you to name the new type, in this case, fruit trees and Add it to the list of types. Then click on the type name to add members. Enter the member names, oranges, apples, pears and passion fruits, clicking Add member after each one.

 

Even more easily, you can read the list of member names in from a file.

 

You can use the enumerated types and members in many situations.

  1. You can dimension a submodel to have the same number of instances as there are members of a type. Simply enter the type name in the dimensions field.
  2. You can use the members names as indices when reading parameter values from a file. This is particularly convenient when the file was used to create the list of member names.
  3. You can use the makearray function to create an array using the test place_in(n)==member to set each value.
  4. You can test equality between an index and a member name. The list is in an arbitrary order, so other functions such as less than, or predecessor, are not supported. This makes enumerated types a less convenient way of representing, e.g. month names.
