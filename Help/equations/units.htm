Physical units

There are two separate (and incompatible) ways of using physical units, such as kg, in Simile models.

 

  • Method I is a method of using units to perform an ad-hoc conversion between values in different systems, without cluttering equations with conversion constants.
  • Method II is a system of entering equations with dimension checking, enforcing consistency and performing the required conversions automatically. There is a system for adding new unit definitions.

 

The first method is the default.  To activate the second method, select the "Yes" option in the drop-down field labelled "Use units in math" in the Model...Properties dialogue box. The options are "Default", "Yes" or "No". The default is to inherit the setting from the parent submodel. In a top-level submodel (i.e. desktop), the default is "No". It is possible to have submodels with units and submodels without in the same model.

 

Method I : Ad-hoc conversions

The default use of the units field in the equation dialogue box is to describe the type of the element’s value, for example, Boolean, integer, or floating point number.  It is also possible to use this field to specify particular physical units, if appropriate.  If used in this way, the value is taken to be a floating point number.

 

Specifying physical units is valuable where it is necessary to convert between flows specified in different units of the same physical quantity.  For example, mass (or more loosely, weight) can be measured in kilograms or pounds.  If a flow with units of pounds/day is linked to a compartment with units of kilograms, the necessary conversion will be performed automatically.  Another flow into the same compartment might be measured in grams/second, and again the conversion would be performed automatically.

Caveats

  1. Unit conversions are only performed for  flows and  compartments.  Conversion is not performed for variables. 

 

  1. Unit conversions are only performed for elements directly connected to one another.  If a compartment measured in pounds is connected to a compartment measured in kilograms by a flow that does not have specified physical units, no conversion will be performed.

 

  1. Flows represent rates of change; the units must be specified as rates, for example, pounds/day (and not simply pounds). 

 

Method II : Fully consistent physical dimensions

When the new system is in force, each equation is checked for consistency of dimensions. Dimensions are physical quantities such as length, time or mass. For example, in the equation speed = distance / time, the dimensions of speed must be length/time. These can be expressed in a variety of units, such as m/s, mph, or knots, which all have the same dimensions. It is not physically reasonable to use units with different dimensions, such as acres. A conversion can be made between any units with the same dimensions by applying numerical conversion factors. These conversion factors are built-in to Simile for all the units it knows, and can be added for other units.

 

Each element can therefore have specified units, from which Simile determines the dimensions. If the dimensions are incompatible, an error results. If the element does not have specified units, then default units are applied, calculated from the elements in the equation. If the element is a parameter (i.e. does not have any influences upon it) and has no units, it is assumed to be dimensionless.

 

When adding or subtracting two quantities, both quantities must have the same dimensions. If they do not also have the same units, it is necessary also to specify a conversion for one or both to the same units. For example, adding one distance in feet to another in metres, it is necessary to either convert the former to metres, the latter to feet, or both to a third unit, such as km. To convert units, edit the unit expression in the equation dialogue box where the elements are being used where the influences are listed. The necessary conversion factors are applied automatically.

 

In the physical sciences, many models can be completely expressed in terms of physically meaningful quantities. In ecology and the social sciences, it is more common to use ad-hoc parameterisation that defies physical interpretation. In these case, it is futile to try and use the new system. The previously existing system for ad-hoc conversion should be used instead, as needed.

 

To add new units, add the definition to the file new_units.pl in the Functions folder, following the format of the units already there. The definition must be in terms of existing units.
